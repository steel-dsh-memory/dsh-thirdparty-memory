DSH Third-Party Long-Term Memory Plugin — Release 0.4.7
=======================================================

Released  : 2026-11-13
Licence   : MIT
Status    : unofficial third-party project, not affiliated with DeepSeek
            or its official teams

Scope
-----
Security and correctness release for the two P1 “load-bearing” findings and
four severe P2 findings from the 0.4.6 audit. Three lighter P2s and all P3s
remain out of scope. Windows is the primary supported platform. Upgrading from
0.4.6 is a drop-in replacement of the plugin files; the memory store is not
touched, migrated or rewritten.

Changes
-------
1. P1-1: the manager default directory works on Chinese Windows.

   The automatic default/legacy store directory no longer fails the ASCII-only
   name check. The check still applies when the user explicitly chooses a
   directory; the saved default is not treated as an explicit user choice.

2. P1-2: a failed legacy JSON migration is visible instead of a silent empty
   library.

   When migration fails, readable old JSON entries are returned with
   `degraded` set; no empty SQLite file is created over the old data. A store
   that cannot be read returns empty with the degraded reason, not a normal
   empty library.

3. P2-1: cross-session ephemeral memories no longer leak.

   Ephemeral entries bound to another session are excluded from the relevant
   index, from dormant/rest and from explicit recall. They cannot appear in
   another session’s prompt or preview. The current session’s ephemeral entries
   stay in the body; legacy unbound ephemeral entries keep the dormant
   behaviour. `all` mode only exposes unbound or current-session ephemeral
   entries.

4. P2-2: `injectMode: all` now really selects all.

   `core.selectEntries` accepts an `all` option. Global/persona entries go to
   `always`, the current session’s ephemeral entries stay ephemeral, and every
   other live entry goes to `matched`, bounded by `maxEntries`; `rest` is empty.
   Keyword thresholds, project activation and `showIndex` no longer hide
   ordinary or project memory in `all` mode. The injected heading is
   “全部记忆（all 模式）”.

5. P2-3: vector decimal configuration is preserved.

   `vectorWeight` and `vectorMinCos` are declared with `integer: false`, so
   `0.3` / `0.5` are no longer rounded to `0` / `1`. The threshold in
   `cordis.patch.yml` now reaches the plugin Config unchanged.

6. P2-4: attach no longer resets user configuration.

   An existing `thirdparty-memory` block is left byte-for-byte untouched when
   `dataFile` does not change. A changed `dataFile` replaces or inserts only
   that line and preserves `enabled`, `autoExtract`, `inbox`, `maxBytes`,
   `vectorMinCos` and user comments. A default block is appended only when no
   block exists.

Upgrade
-------
1. Replace the plugin files (or unpack the new manager exe). Keep the data
   folder as-is — the upgrade swaps code only and never overwrites, migrates,
   renames or deletes a memory file.
2. Re-run the installer if needed: attach.ps1 -Repair, then attach.ps1 (or the
   exe’s “Attach to DSH…”).
3. Completely exit and restart DSH so the new core.js/index.js are loaded.
   The manager exe takes effect on its next launch.
4. The exe is unsigned; Windows SmartScreen may warn.

Known limits (remaining, not fixed in 0.4.7)
--------------------------------------------
- Memory page parses only the YAML enabled/autoExtract/inbox switches; its
  preview/dashboard can disagree with the real injection config, and saving
  can overwrite maxBytes and similar keys.
- Manager ChangePort saves config and stops the old service before checking
  whether the new port is occupied.
- judgeMode (model / rules / off) is still not in the plugin Config; all modes
  run the same rule-based extraction when autoExtract is on.
- P3 items are untouched.
- The JSON fallback path still has no revision lock, so two writers can
  overwrite each other there.
- Retrieval is literal matching (CJK n-grams plus local hash vectors), not
  synonym-level semantics; the “extract everything about X” phrase pattern is
  Chinese-only.
- The manager exe is unsigned; SmartScreen warnings are expected.
